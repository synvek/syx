# SYX standard library packages

Embedded modules shipped with the toolchain. Import with `import Name` (for example `import Os`, `import Net`).

The builtin type inventory lives in [`internal/manifest.json`](internal/manifest.json) (regenerated by the driver build; see below).

## Packages

| Package | Import | Status | Notes |
|---------|--------|--------|-------|
| **Core** | (prelude + `import` of named modules) | Stable / evolving | Builtins, protocols, `Math`, `Concurrency`, `JSON`, `Path`, `SIMD`, … |
| **Os** | `Os` | MVP | CPU, memory, user/home, hostname, uptime, disk, load, primary IPv4 |
| **Net** | `Net` / types in package | Partial | HTTP client, URL, TCP/UDP, DNS, TLS client; not full server TLS or streaming GA |
| **IO** | `IO` | Stable / MVP | Files, streams, handles, watchers |
| **Process** | `Process` | Stable / MVP | Prefer `ProcessBuilder` / `Child` for cwd, env, kill, timeout |
| **Sync** | `Sync` | Stable | Channels; actors via Core `Concurrency` |
| **Text** | `Text` | Stable / MVP | `Fmt`, regex, encoding helpers |
| **DateTime** | `DateTime` | MVP | Calendar time, durations, clocks |
| **Crypto** | `Crypto` | Experimental | Hashing, HMAC, AES-GCM, Ed25519, PBKDF2, random bytes |
| **Data** | per-file modules | Partial | SQL, ORM, XML, Codable helpers |
| **Linalg** | `Linalg` | Experimental | Packed `Mat` (plugin-backed); not a Core prelude type |
| **Di** | `Di` | Experimental | Service locator / DI |
| **UI** | `UI` | Deferred | SynUI host bridge; product GA not ready |
| **Log** | `Log` | MVP | Leveled + structured field logging |
| **Trace** | `Trace` | MVP | Spans; not full OpenTelemetry |
| **Metrics** | `Metrics` | MVP | Counter / Gauge; not Prometheus/OTel export |
| **Profiler** | `Profiler` | MVP | Wall-clock / CPU sections; not sampling/pprof GA |
| **Testing** | `Testing` | Stable | `assert` / `assertEq` / `test` helpers for `syx test` |
| **Observation** | `Observation` | MVP | KVO-style observe |
| **internal** | — | Tooling only | Manifest, capability tables; not a user import |

Status labels are coarse: **Stable** usable in apps, **MVP** usable with gaps, **Partial** / **Experimental** evolving APIs, **Deferred** not product-ready.

## Generated sources (do not hand-edit)

Fixed-width and platform numeric types under `core/builtins/numeric/` are produced from templates by `syx-driver`’s `build.rs`. Hand-editing the generated `.sy` files will be overwritten on the next `cargo build -p syx-driver`.

**Edit instead:** [`core/builtins/_templates/`](core/builtins/_templates/) (`*.sy.in` and `fragments/*.sy.in`), then rebuild the driver.

### Hand-authored (safe to edit)

These are **not** overwritten by the numeric template pipeline:

- `core/builtins/numeric/bigint.sy` (`BigInt`)
- Other builtins: `collections/`, `scalar/`, `text/`, `reference/`, `algebraic/`, `special/`
- `core/protocols/*.sy`
- All non-Core packages (`os/`, `net/`, `io/`, …)

When adding new fixed-width numeric APIs, extend the templates (and the numeric specs in `crates/syx-driver/build.rs`) rather than patching generated files, so later expansions do not conflict with regeneration.
